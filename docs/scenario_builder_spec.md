# シナリオビルダー仕様 (地域 → 集落 → 旅路 → 遺跡)

`/ai ビルダー` (`builder` / `gui` / `シナリオ` でも可) で開く 4 段階のシナリオビルダーの仕様です。
各段階で AI が下書きを作り、GM が手直しして【AI World Atlas】ジャーナルに保存し、次の段階の前提にします。
旅路と遺跡は、そのままシーン (マップ・壁・照明・部屋ノート) として構築できます。

目標は 2 つです。

- **整合性**: ワールド資料と上位の段階に食い違わない。段階をまたいで名前・場所・時代・人物がぶれない。
- **マンネリ防止**: 何度作っても同じ話 (霧・古代の魔力機関・行方不明の子供…) にならない。

## 1. 整合性のしくみ

### 1.1 優先順位

すべてのプロンプトに同じ順位を明記します。下位は上位と矛盾してはいけません。

1. GM 指示 (画面の「GM 指示」欄、GM が自分で付けた名前)
2. ワールド資料 (FVTT のワールド説明と、画面上部で選んだ参照ジャーナル)
3. 確定事項 (上位段階の canon)
4. 上位段階の本文 (公開情報・DM 情報)
5. 発想カード

GM 指示で確定事項を上書きしたときだけは許し、AI に `consistency_notes` で申告させます。申告は GM の画面に通知されます。

### 1.2 確定事項 (canon) と未回収の伏線 (open_threads)

各段階の出力に次の 2 つを含めます。

- `canon`: 後の段階が変えてはいけない事実を「種別: 内容」で 5〜8 件 (例: `資源: 塩は南の干潟で採れる`、`命名の作法: 柔らかい母音の二語`)。
- `open_threads`: 後の段階に回収してほしい伏線 (DM 向け)。次の段階は少なくとも 1 つを回収・発展させ、`resolved_threads` に書きます。

どちらも画面で編集でき (1 行 1 件)、保存すると atlas_meta flag と DM 専用ページ「📌 確定事項と伏線」に入ります。
後の段階のプロンプトには、ページの文章ではなく flag の構造化データを渡します。

### 1.3 固有名詞台帳と命名の作法

上位段階・地図帳の全エントリ・Actor の名前を「固有名詞台帳」として渡し、次の 2 つを禁じます。

- 既にある名前を、別のものに付ける
- 同じものに別の名前を付ける

地域の段階で `naming_style` (響き・語の組み立て・例 2 つ) を決めさせ、確定事項に入れます。以後の名前はこの作法に従います。

### 1.4 因果の糸

「新しく作る要素は、上位の何かから因果で説明できること」をルールにし、とくに 2 本の流れを切らないよう指示します。

- 物の流れ: 地域の資源 → 集落の一次・二次産業 → 手仕事の品 (`micro_craft.made_from`) → 旅路の痕跡 → 遺跡での使われ方
- 人の流れ: NPC の望み (`want`) → 隠し事 → 遺跡の勢力との関わり

遺跡は地域の歴史の層 (`history_layers`) のどれかの時代に建てられたことにします (`era`)。

### 1.5 区画の役割はサーバーが先に決める

遺跡の区画は 5 区画ずつ並列に AI へ問い合わせるため、AI 任せだと中目標が重複したり空室の割合がぶれたりします。
そこで、問い合わせる前にサーバー (`plan_site_rooms`) が全区画の役割を決め、全ジョブに一覧を渡します。

| 役割 | 決め方 |
|---|---|
| 入口・最深部 | 生成器の start / goal |
| 中目標 | `target_topology` が hub ならハブ (接続 3 以上)、それ以外は袋小路 (接続 1)。入口から最深部までの深さに散らばるように置く |
| 休憩・空室 | 残りの約 3 割 (休憩は中ほどの深さに 1 つ) |
| 財宝・罠 | 残りの袋小路に交互に |
| 遭遇・手がかり | 残りのハブ・周回路・通路 |

AI が返した `role` は使わず、この割り当てで上書きします。AI の情景が返ってこなかった中目標の区画にも、バッジと GM メモは付けます。

### 1.6 公開と秘密の分離

`public_lore` (プレイヤー公開ページ) と `dm_secrets` (DM 専用ページ・所有権 NONE) を出力の段階で分け、
「公開情報は秘密と矛盾しない表の顔にする」「真相・黒幕・罠の場所は DM 情報にだけ書く」を指示します。

## 2. マンネリ防止のしくみ

### 2.1 発想カード

`tools/scenario_decks.py` に段階ごとの「軸」とカードを持ち、サーバーが各軸から 1 枚ずつ引いてプロンプトに必須の制約として渡します。

| 段階 | 軸 |
|---|---|
| 地域 | 地形の主役 / 気候の癖 / 歴史の断層 / 暮らしを支える産物 / ひとつだけの異物 |
| 集落 | 共同体のかたち / 習わし・祭り / 悲しみの型 / 意外な担い手 |
| 旅路 | 道の性格 / 旅の圧力 / 道中の出会い |
| 遺跡の前提 | ミッションの型 (11 種) / 主な敵の動機 / ひねり / 建物の元の用途 |

- カードは「この世界に合わせて解釈する」前提の短い種です。ワールド資料や確定事項と衝突したら AI が読み替えます (順位はカードが最下位)。
- どう使ったかを `design_notes` に 1 枚 1 行で書かせ、DM 欄の「設計メモ」に表示します。
- 引き方は seed で再現できます。seed とカード id は地図帳の flag に保存します。
- **最近の地図帳エントリ 12 件とこの画面で引いたカードは、次の抽選で避けます** (その軸の候補が尽きたら戻す)。

### 2.2 既存エントリとの重複禁止

地図帳の目次 (カテゴリ・名前・確定事項の先頭 3 件) を渡し、同じ主題・同じ構図 (同じ悲しみ、同じ黒幕の型、同じ天候を主役) を繰り返さないよう指示します。

### 2.3 ありがちな表現の禁止と具体性

AI が寄りがちな表現 (霧に包まれた / 古代の魔力機関 / 封印が解ける / 闇の儀式 / 選ばれし者 / 行方不明の子供たち など) を禁止リストにします。
ただしワールド資料か確定事項にあるものは使えます (世界の設定が優先)。
「神秘的な」「不気味な」のような抽象的な形容を禁じ、物・数・手触り・音・におい・誰の仕業かで書かせます。
読み上げ文は、地点・区画ごとに主役の感覚を変え、同じ名詞を 3 か所以上で繰り返さないようにします。

### 2.4 期待を 1 つだけ裏切る

各段階に「期待を 1 つだけ裏切る要素」(例: 恐れられている者が実は守り手) を入れさせます。ただし整合性ルールは破りません。

## 3. 段階ごとの入出力

| 段階 | 主な入力 | 主な出力 |
|---|---|---|
| 地域 (`region`) | ワールド資料・GM 指示 | 地形と気候、資源 2〜3、歴史の層 2〜3、命名の作法、見えざる脅威 |
| 集落 (`settlement`) | 地域・規模 | 一次/二次産業、手仕事の品 (材料つき)、楽しみと悲しみ、NPC (望みつき) |
| 旅路 (`wilderness`) | 地域・集落・地点グラフ (seed から生成した 9 地点) | 本道と迂回路、天候表、ランドマーク (グラフと同じ 0 始まりの id) |
| 遺跡の前提 (`site_lore`) | 集落・旅路 (地域は親から補完)・PC/NPC | 大目標、中目標 2〜3 (dead_end / hub)、逆転の展開、時代と元の用途、勢力 |
| 遺跡の区画 (構築時) | 上記すべて + 編集済みの公開/DM 本文 + 区画の役割の割り当て | 区画ごとの名称・読み上げ・GM メモ・照明 |

全段階で `canon` / `open_threads` / `resolved_threads` / `design_notes` / `consistency_notes` を返します。
AI の応答が使えない形 (名前や公開情報が無い) のときは、手直し用の骨組みを返して GM に知らせます。

### 3.1 集落と旅路は 2 回に分けて問い合わせる

1 回で全部を書かせると応答が長くなり、AI の待ち上限 (agy なら既定 300 秒) を超えやすいため、骨組みを先に決めてから細部を書かせます。
細部の回には骨組みを「確定」として渡すので、分けても名前や真相はぶれません。

| 段階 | 1 回目 (骨組み) | 2 回目 (細部) |
|---|---|---|
| 集落 | 名前・公開情報・NPC の名前/立場/望み・悲しみの真相 (1〜2 文)・canon | NPC の人柄・隠し事・手仕事の品の手がかり・BGM・open_threads (`builder_settlement_secrets_prompt.txt`) |
| 旅路 | 全体像・天候表・秘密・canon・`landmark_plan` (全地点の名前/役割/野営可/主役の感覚) | 地点ごとの読み上げ・GM メモ・照明・アイコン。5 地点ずつ (Gemini は並列、agy は 1 本ずつ) (`builder_wilderness_landmarks_prompt.txt`) |

- 2 回目は骨組みの内容を上書きしません (NPC は名前で突き合わせて人柄だけ足す。`sorrow_truth` は骨組みが優先)。
- 2 回目が失敗・打ち切りになっても骨組みは返し、「細部の一部を受け取れなかった」と GM に知らせます。
  描写の無い地点は、骨組みの役割 (`purpose`) を GM メモに入れます。

### 3.2 遺跡のシーンは地図を先に作り、区画は書けたものから反映する

遺跡の地図・壁・区画の配置はジェネレータ (`tools/dungeon_generator.py`) がシード値から作るので、AI を待たずに数秒でできます。
「保存してシーン構築」では、まず仮の区画名 (役割の割り当てだけ反映) でシーンと探索録を作り、AI が区画の情景を書き終えたものから
`update_dungeon_rooms` で名前・読み上げ・GM メモ・照明・アイコンを差し替えます。打ち切りや失敗で書けなかった区画は仮の名前のまま残ります。

シーン構築中もビルダー画面に「⏳ シーンを構築中です…」と工程・経過・残り秒を出します (下書き作成と同じ行)。
画面上部の「⏱️ タイムアウトしたら自動で延長する」(既定 OFF) を入れると、タイムアウト時に確認カードを出さずに最大 5 回まで自動で延長します。
- 待ち上限は 1 回ごとにかかります (旅路の 2 回目は 1 回の上限 × 並列で回す段数)。

## 4. 地図帳ジャーナル

`【AI World Atlas】/1_地域 (Regions)` などのフォルダに 1 エントリ = 1 JournalEntry で保存します。

| ページ | 所有権 | 内容 |
|---|---|---|
| 📖 プレイヤー公開情報 | OBSERVER | 公開情報 (エスケープ済みの段落) |
| 🔒 DM専用情報 | NONE | DM 情報 + 設計メモ |
| 📌 確定事項と伏線 | NONE | canon と open_threads |

`flags["ai-gm-bridge"].atlas_meta`: `categoryKey`, `updatedAt`, `parent_ids` ({region, settlement, wilderness}), `canon`, `open_threads`, `cards`, `seed`, `map` (旅路の地点グラフの seed と生成条件), `landmarks`, `sub_objectives`, `site_mode`, `audio_prompts`。

画面の「既存の地図帳を開く」でエントリを読み込むと、本文・確定事項・ランドマーク・中目標が戻ります (L11: ブラウザを再読み込みしても旅路を構築できる)。
画面上部で選んだ参照ジャーナルは GM のユーザー flag (`builder_reference_ids`) に保存します。

## 5. 制限

- マップ規模は小・中のみ (M12: grid 100px 固定のため、大・特大はシーンが巨大になる)。
- BGM・環境音の生成 (`audio_prompts`) は Phase 5 で使います。今は地図帳の flag に保存するだけです。
